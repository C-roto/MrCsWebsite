すべての要素が\(N\)以下のピタゴラス数を探すプログラムについて


\(a^2+b^2=c^2\)かつ\(a < b < c\)を満たす正整数の組\((a,b,c)\)をピタゴラス数と呼称する。
以下のような問題を考える。
3つの正の整数の組\((a,b,c)\)であって、\(a^2+b^2=c^2\)かつ\(a < b < c\)を満たすものを「ピタゴラス的組」と呼ぶことにする。
2つの相異なるピタゴラス数の組\((a_1,b_1,c_1), (a_2,b_2,c_2)\)に対して、辞書順を以下のように定義します。
(1) \(c_1 < c_2\)ならば、\((a_1, b_1, c_1)\)の方が\((a_2, b_2, c_2)\)よりも辞書順で小さい。
(1) \(c_1 = c_2\)かつ\(b_1 < b_2\)ならば、\((a_1, b_1, c_1)\)の方が\((a_2, b_2, c_2)\)よりも辞書順で小さい。
これによりすべてのピタゴラス的組に対して、一意に辞書順が定まることが示せます。

正の整数\(N\)が与えられます。
全ての要素が\(N\)以下であるようなピタゴラス的組を辞書順で小さいものから順に出力してください。
ただし、\(1 \leqq N \leqq 10^6\)とし、計算はおよそ20秒以内で終了することが望ましいです。

小問題1に対する解

もっとも単純なプログラムは以下のようなものだろう。

N = int(input())

for c in range(1, N + 1):
    for b in range(1, c):
        for a in range(1, b):
            if a ** 2 + b ** 2 == c ** 2:
                print(a, b, c)
上記のプログラムだが、時間計算量\(\Theta (N^3)\)のプログラムである。
どれくらいかというと、\(N=10^2\)は1秒以下で実行が終わるが、\(N=10^3\)になるとこの時点で10秒の制約を超えそうになる。多分\(N = 10^4\)だと絶対にオーバーする。
正しいアルゴリズムだが、遅すぎるというわけである。

小問題2に対する解

時間計算量\(\Theta (N^2)\)のプログラムを実装してみる。

N = int(input())

square = dict()
for i in range(1, N + 1):
    square[i ** 2] = i
for a in range(1, N + 1):
    for b in range(1, a):
        if a ** 2 - b ** 2 in square:
            if b < square[a ** 2 - b ** 2]:
                print(b, square[a ** 2 - b ** 2], a)
アイデアの根幹は「\(a^2+b^2\)が平方数かを素早く判定する」という点にある。
\(a\)を\(1\)から\(N\)まで、\(b\)を\(a+1\)から\(N\)までループさせるという部分は変わらない。3重目のループを軽くするわけだ。
そのためには、\(c \leqq N\)なので\(c^2 \leqq N^2\)であるから、\(N^2\)以下の平方数をすべて列挙しておいて、\(a^2+b^2\)が平方数かどうかをすぐにチェックできるようにしておけばいいのではないだろうか。
set型を活用し、平方数を列挙する方針を取った。
\(N=10^3\)程度なら1秒以下で回るし、\(N=10^4\)だとちょっと遅いが、まあ計算できる。\(N=10^5\)は多分、20秒は無理。

小問題3に対する解

さて、現状考えうる中で、上の2つより早いプログラムはあるだろうか。実は、ある。
以下のプログラムにて、各要素が与えられた正整数\(N\)以下のピタゴラス数をもれなくダブりなく表示でき、かつその時間計算量が\(O (N\log_{}{N})\)であることを示す。

def gcd(x, y):
    if x < y:
        x, y = y, x
    while y != 0:
        x, y = y , x % y
    return x

def floor_sqrt(x):
    L = 0
    R = x
    mid = (L + R) // 2
    while L < R:
        if mid ** 2 == x:
            return mid
        elif mid ** 2 > x:
            R = mid
        else:
            L = mid + 1
        mid = (L + R) // 2
    if mid ** 2 == x:
        return mid
    else:
        return mid - 1

N = int(input())

results = []
counter = 0
# 時間計算量はO(NlogN)程度で、まあまあ早い
# ループは(\sqrt{N})^2=N回回る
for p in range(1, floor_sqrt(N) + 1):
    for q in range(p + 1, floor_sqrt(N) + 1):
        # 原始ピタゴラス数の可能性がある3つ組(a,b,c)を生成
        a = q ** 2 - p ** 2
        b = 2 * p * q
        c = q ** 2 + p ** 2
        if a > b:
            a, b = b, a
        # cがNより大きければループを打ち切る
        if c > N:
            break
        # 全て互いに素なら原始ピタゴラス数である
        if gcd(gcd(a, b), c) == 1:
            # その原始ピタゴラス数から生成できるピタゴラス数をすべて生成する
            t = 1
            while t * c <= N:
                results.append([t * a, t * b, t * c])
                counter += 1
                t += 1
results.sort(key=lambda x: (x[2], x[1]))

for p, q, r in results:
    print(p, q, r)

このアルゴリズムが正当であることを示す（停止性については自明としてよいだろう）。
まず、各要素が互いに素ではないピタゴラス数は、各要素の最大公約数で各要素を割ることにより、各要素が互いに素なピタゴラス数になる。割った後の各要素は、元が\(N\)以下なら勿論\(N\)以下である。
よって、各要素が\(N\)以下で、かつ互いに素であるピタゴラス数を全列挙し、それらすべてに対し、1以上の整数を各要素に掛けてみるという方法で、\(N\)以下のピタゴラス数をすべて生成することができる。
各要素が互いに素であるピタゴラス数を、以下「原始ピタゴラス数」と呼ぶ。
ここで、以下の補題を用いる。
【補題】
任意の原始ピタゴラス数\((a,b,c)\)に対して、ある正の整数の組\((m,n)\)が存在して、以下の等式のうちいずれかを満たす。
\(a = m^2 - n^2, b = 2mn, c = m^2 + n^2\)
\(a = 2mn, b = m^2 - n^2, c = m^2 + n^2\)
証明は色々調べると出る。要は\(\frac{c - b}{2},\frac{c + b}{2}\)が平方数になることを示せばよい。
これを利用することで、\(c = m^2 + n^2\)と書けるので、\(m = 2 ～ \lfloor \sqrt{N} \rfloor, n = 1 ～ m - 1\)までループを回せば\(N\)以下の原始ピタゴラス数はすべて列挙できる。
このループの中で実際に\(a,b,c\)を計算する部分はほぼ定数時間とみなせるため、ループ全体での原始ピタゴラス数を求める部分の時間計算量は\(O(N)\)で抑えることができる。

次に、原始ピタゴラス数からピタゴラス数を生成する過程を考える。
これはループ条件に書いてある通りで、各原始ピタゴラス数\((a,b,c)\)について\(1 \leqq t \leqq \frac{N}{c}\)を満たす整数\(t\)の個数のピタゴラス数を生成できる。
よって、\(N\)以下の原始ピタゴラス数の集合を\(P_N\)とすると、\(N\)以下のピタゴラス数は全体でおよそ
\(\displaystyle \sum_{(a,b,c) \in P_N} \frac{N}{c}\)
個だけ存在する。これは先ほど原始ピタゴラス数を求めた時の結果から
\(\displaystyle \sum_{(a,b,c) \in P_N} \frac{N}{c} \leqq \sum_{m,nは整数, m < n, m^2+n^2 \leqq N} \frac{N}{m^2 + n^2}\)
と押さえることができる。これはさらに以下のように変形できる。
\(\begin{align} \sum_{m,nは正の整数, m > n, m^2+n^2 \leqq N} \frac{N}{m^2 + n^2} \\ = \sum_{m = 2}^{\lfloor \sqrt{N} \rfloor} \sum_{n = 1}^{m - 1} \frac{N}{m^2 + n^2} \\ < \sum_{m = 2}^{\lfloor \sqrt{N} \rfloor} \sum_{n = 1}^{m - 1} \frac{N}{m^2} \\ \leqq \sum_{m = 2}^{\lfloor \sqrt{N} \rfloor} \frac{N \cdot (m - 1)}{m^2} \\ < \sum_{m = 2}^{\lfloor \sqrt{N} \rfloor} \frac{N}{m} \\ = N \cdot \sum_{m = 2}^{\lfloor \sqrt{N} \rfloor} \frac{1}{m} \\ < N (1 + \log_{}{\sqrt{N}}) \end{align}\)
ただし、最終行での変形には調和級数を対数関数で押さえられることを用いた。積分などを使えば高校範囲で証明可能である。
つまり、\(N\)以下のピタゴラス数全体は\(N (1 + \frac{1}{2} \log_{}{N})\)より少なく、特に\(O(NlogN)\)個だと言える。
各ピタゴラス数の出力は単なる数値計算であり、定数時間でできると見なすと、ループ全体での時間計算量は確かに\(O(NlogN)\)で押さえられると分かった。

以上より、プログラムの各部に関して、ネックとなる場所の動作時間は\(O(NlogN)\)で押さえられることが分かったので、全体としてもこれで押さえることができた。

このコードだと、\(N=10^6\)をピックアップするのに15秒程度で済む。早いね。
