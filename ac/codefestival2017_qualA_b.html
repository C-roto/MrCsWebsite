CODE FESTIVAL 2017 qual A B fLIP

問題文はこちらから。
行と列の色反転を使って、指定の個数の黒マスをちょうど得られるかを調べる問題。

色の反転について、常に行全体か列全体を反転する性質上、「どこの行/列を反転したか」は重要でなく、「いくつの行/列」を反転したかが重要となる。
また、操作の順番も重要ではない（各マスについて操作が行われた回数の偶奇だけが最終的な色に寄与し、それは今見ているマスが属する行と列それぞれで操作が行われたかのみに関係するから）。
行と列の個数の組み合わせは全体で\((N+1)(M+1)\)個しかないわけだから、すべてについていくつの黒マスが得られるかを全列挙して、その中に\(K\)があるかを調べればよい。

今、\(i\)個の行と\(j\)個の列について反転操作を行ったとしよう。
操作順は関係ないので、一旦列に関する操作のみを行い、まとめて行に関する操作を後で行ったとしよう。
すると、列に関する操作を終えた時点で黒マスの個数は\(Mi\)個になる。
この後、行に関する操作を1回行うと、その列の中には黒マスが\(j\)個、白マスが\(N-j\)個あるから、1回の操作ごとに黒マスの個数は\(-i+N-i=N-2i\)個ずつ増減する。
この操作を\(j\)回行うことで、行に関する操作全体で\(j(N-2i)=Nj-2ij\)個の黒マス増減が発生する。
よって、全体として得られる黒マスの個数は\(Mi+Nj-2ij\)個になる。これを\(0 \leqq i \leqq N\)と\(0 \leqq j \leqq M\)について考え、最終判定をすればよい。

各回でいくつの黒マスが得られるかは定数時間で計算できるから、ループの回数が全体の計算量に最も影響を与える。
全体の時間計算量は\(O(NM)\)で抑えることができ、これはこの制約下では充分に高速だろう。実装例は以下の通り。

N, M, K = list(map(int,input().split()))

# スイッチは合計何個押したがだけが重要で、左から順に押した後、上から順に押すとしても問題ない。
# 左からi行、上からj列までを押したときの黒マスの個数はNj + Mi - 2ij個

# あり得る黒マスの個数をすべて列挙
check = set()
for i in range(N + 1):
    for j in range(M + 1):
        check.add(N * j + M * i - 2 * i * j)

# ありうる黒マスの個数の中にKはある？
if K in check:
    print('Yes')
else:
    print('No')
緑diffではあるけど古い問題ではある。現代基準だとどの程度だろう。茶か、下手したら灰か。
もっと"緑然"とした問題を解けるように力をつけていきたいところ。
