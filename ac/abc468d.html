ABC468D Pre-Palindrome

問題文はこちらから。 1文字以下を変えて回文になる部分文字列を調べ上げる問題。

回文と言えばローリングハッシュ(そうか？)。しかし今回は「1文字違う」を許容するとのこと。
1文字でも違うとハッシュ値はめちゃくちゃ変わりうるので、こういう方針ではないっぽい。
制約を見ると\(N \leqq 10^4\)とのことで、なんかちょっと小さい。
時間計算量\(O(N^2)\)ぐらいまでは許してもらえそうだ。
となると、あり得る全部の連続部分文字列を列挙して確かめるのが良いだろう。
とはいえ、例えば「始点と終点を指定して条件を満たすか調べる」みたいなことをやると、時間計算量\(O(N^3)\)ぐらいになってしまって普通にオーバーしてしまう。
今回は「どこが真ん中になるか」で考えてみる。これなら指定すべき場所は\(N\)のオーダー箇所になるし、各箇所についてざっくり探索時間は\(O(N)\)程度になるので、時間計算量は\(O(N^2)\)で収まりそうだ。
真ん中としてあり得るのは、
・\(i\)文字目
・\(i\)文字目と\(i+1\)文字目の間
の2パターンあるので、各パターンに対して\(i=0,1,...,|S|-1\)までを試せばよろしい（下のパターンは\(|S|-2\)まで）。
実装例は以下の通り。

S = input()

answer = 0
# ちょうど真ん中がi文字目であるような良い文字列はいくつ？
for i in range(len(S)):
    good_flag = True
    for j in range(len(S)):
        if 0 <= i - j and i + j <= len(S) - 1:
            if S[i - j] == S[i + j]:
                answer += 1
            elif good_flag:
                good_flag = False
                answer += 1
            else:
                break
        else:
            break
# i文字目とi+1文字目の間が真ん中であるような良い文字列はいくつ？
for i in range(len(S) - 1):
    good_flag = True
    for j in range(len(S)):
        if 0 <= i - j and i + 1 + j <= len(S) - 1:
            if S[i - j] == S[i + 1 + j]:
                answer += 1
            elif good_flag:
                good_flag = False
                answer += 1
            else:
                break
        else:
            break

print(answer)
「文字列が特定の条件を満たすか？」とか「文字列が〇〇と一致するか？」みたいな問題は色々な方法があって難しい。
動的計画法を使う場合もあるし、ローリングハッシュを使う場合もあるし、今回みたいな問題の可能性もある。
大事なのは「何が来たらこれ」のようなパターン暗記ではなくて、「問題文はこう言っているから、それに適した手法ってこんなのがあったな(或いは全探索で事足りるな)」と考えることのような気がする。
私も不肖にして知識やひらめきは足りない方だと思うが、とりあえず考えてみることはやりたい。
