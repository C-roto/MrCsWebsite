ABC222D Between Two Arrays


問題文はこちら。

広義単調増加列に「挟まれる」数列の個数を求める。
問題文から\(C\)もまた広義単調増加になるということと、同一視できるものが多そうなことから、動的計画法で解けないかを検討したくなる。

何をdpテーブルに持たせればよいかを考える。
シンプルに「\(i\)番目まで数列を作ったとき、末尾が\(c(ただしa_i \leqq c \leqq b_i)\)であるようなものの個数」を考えてみよう。
すると、「\(i-1\)番目までの末尾が\(c\)以下であるものの個数」が知りたい値になるはずである。
「以下」というのが曲者で、\(c\)の値がとりうる範囲によっては最悪の時間計算量が\(O(N \cdot max(b_i)^2)\)程度になってしまうので、この制約下ではとても遅い。

こういう場合は「\(i-1\)番目までの末尾が\(c\)以下であるものの個数」を先に計算しておくのが良い。
よく「累積和」と呼ばれるものである。詳細はまた別にまとめる……かも。
累積和の考え方を使うと、前計算部分にかかる時間はざっくり\(O(N \cdot max(b_i))\)程度であると見積もれる。
動的計画法パートは\(O(N \cdot max(b_i))\)程度で計算できるだろうから、全体としてもやはりこの程度の時間計算量で収まると考えられる。

それで、上記の問題に対する答えをメモしておき、\(i=N\)かつ\(c=a_i,a_i + 1,...,b_i\)の時の答えをすべて足せば、知りたかった元々の問題の答えが分かる。

DPテーブルのほかに情報を格納しておいて、それを使うという発想の問題をあまり見たことがなかったので、そういう方針もありだと学べた。
実際にACしたコードは以下の通り(コメントを追加or位置を調整した)。

N = int(input())
A = list(map(int,input().split()))
B = list(map(int,input().split()))

mod = 998244353
M = max(max(A), max(B))

# i番目の要素までを見たとき、それがc以下であるようなものの個数をdp[i][c]としてDP
dp = [ [ 0 for _ in range(M + 1)] for _ in range(N)]
rowsum = [ [0 for _ in range(M + 1)] for _ in range(N)]

# 初期状態の計算と累積和
for i in range(A[0], B[0] + 1):
    dp[0][i] = 1
    rowsum[0][i] += 1
for i in range(1, M + 1):
    rowsum[0][i] += rowsum[0][i - 1]

for i in range(N - 1):
    # i番目までを見たとき末尾がj以下の数列の個数をdp[i+1][j]に格納
    for j in range(A[i + 1], B[i + 1] + 1):
        dp[i + 1][j] += rowsum[i][j]
    # 累積和計算の前準備
    for j in range(M + 1):
        rowsum[i + 1][j] = dp[i + 1][j]
        rowsum[i + 1][j] %= mod
    # 実際に累積和計算
    for j in range(1, M + 1):
        rowsum[i + 1][j] += rowsum[i + 1][j - 1]
        rowsum[i + 1][j] %= mod

answer = 0
for i in range(A[-1], B[-1] + 1):
    answer += dp[-1][i]
    answer %= mod
print(answer % mod)
横着してDPテーブルに全部の情報を載せようとしてWAしたのと、配列rowsumの値をmod取らずに格納してMLEしたというミスで2ペナ貰っている。
本番のコンテストだったら嫌だな～。
個人的にPythonの良いところと感じているのは「思いついた実装をとりあえず形にできること」だと思っているので、「累積和の情報を管理する配列を用意しておけばいいよね～」と思ったらとりあえずそうして実装してから簡略化を考えるべきだったかもしれない。
解けたはいいが反省の残る1問だった。
