ABC321D Set Menu

問題文はこちらから。
セットメニュー全体の合計金額を求める問題。

主菜と副菜全部の組み合わせについて個別に計算すると、時間計算量は\(O(NM)\)になってしまい、この問題の制約下だと遅すぎる。
一方で、主菜だけの金額の総和は簡単に求まる。\(P\)の存在を一回忘れると、各副菜についてその副菜を用いるセットメニューの総和は「主菜だけの金額の総和」+「副菜の金額×主菜の個数」になる。
そうなると、主菜の金額の総和を求めておくと、全体の時間計算量が\(O(N)\)まで減る。これはこの制約下なら早い。
\(P\)の存在をどうするかだが、\(A\)を昇順にソートしておけば二分探索をすることで、副菜\(B\)を固定した際の「\(A[i]+B\)の値が\(P\)を超えない境界となる\(i\)」を時間計算量\(O(\log{N})\)で求めることができる。
よって、主菜の総和は累積和などで求めておき、必要な部分だけ取り出して使うなどすれば、全体の時間計算量は\(O(M\log{N})\)になって、この制約下なら十分に高速となる。
実装例は以下の通り。

import bisect

N, M, P = list(map(int,input().split()))
A = list(map(int,input().split()))
B = list(map(int,input().split()))

A.sort()
B.sort()

Sa = [ 0 for _ in range(N)]
Sa[0] = A[0]
for i in range(1, N):
    Sa[i] = Sa[i - 1] + A[i]

answer = 0
for i in range(M):
    x = bisect.bisect(A, P - B[i])
    answer += P * (N - x)
    if x > 0:
        answer += Sa[x - 1] + (B[i] * x)
print(answer)
二分探索+累積和ってなると、本当に典型という感じがする。
瞬発的に解くことができるようにしたい。
