ABC390D Stone XOR

問題文はこちらから。
石を移動した後にXORする問題。

石を移し替える操作は\(N-1\)回だが、これを愚直にやると流石に計算回数が多すぎる。
だが、「最終的にどの袋同士がマージされたか」に注目すると、パターンの数が一気に減る。
これは要するに区別がつくボールN個（つまり最初に袋に入っていた石の数たち）を、区別のつかない箱N箱（つまり袋）に入れる方法の数であるから、ベル数\(B(N, N)\)と一致する(ベル数自体は覚えていなかったが、写像12相のどっかにあったやつだなあと思って検索したらすぐに見つかった)。
\(B(12, 12) < 5 \times 10^6\)程度なので、答えの個数もこれ以下である。これらを全列挙してxorを取る方針というのは悪くなさそうに思える。
実装例では「今残っているうち袋の番号が最大のもの」が属するグループを、ビット全探索の要領で全列挙して、残ったもの同士で再帰的に同じようにグループを作って、最終的に各グループの和同士でXORを取るような感じで書いた。グループの分け方は本質ではないから、各グループの和と、まだ使っていない袋のインデックスだけ残す形で書いた。
時間計算量は\(O(NB(N, N))\)程度で、PyPyだと定数倍などもあり超ギリギリだが、なんとか通った。

def stones_xor(array):
    res = 0
    for i in range(len(array)):
        res ^= array[i]
    return res

global answers
answers = set()

def devides(remains, sums):
    if len(remains) == 0:
        answers.add(stones_xor(sums))
        return
    p = remains.pop()
    n = len(remains)
    for i in range(2 ** n):
        tmp = []
        check = A[p]
        for j in range(n):
            if (i >> j) & 1 == 0:
                tmp.append(remains[j])
            else:
                check += A[remains[j]]
        devides(tmp, sums + [check])

N = int(input())
A = list(map(int,input().split()))
devides([i for i in range(N)], [])
print(len(answers))
