ARC154B New Place

問題文はこちらから。 先頭の文字を好きなところに挿入して、最小手数で目的の文字列を作る問題。

まず、\(S\)と\(T\)を構成する要素が違ったら何度やっても絶対にうまくいかない。
逆にそうでないときは、挿入ソートの要領で変形できることは分かる（後ろの方に挿入していく）。
\(S\)の連続する先頭の何文字かを削った文字列であって、\(T\)の部分列(連続しているとは限らない)になっているもののうち、削った文字数が最も少ないものを\(M\)とする。
この時、\(|S| - |M|\)回操作をすれば\(S\)を\(T\)に一致できる。先述の通り、挿入ソートの要領でうまくいく。
逆に、\(|S| - |M|\)回未満の操作で一致しないことも分かる。
もし\(|S| - |M|\)回未満の操作回数\(X\)回で一致したとし、操作後の\(S\)を\(S'\)と書くことにする。
ここで、\(S'\)から\(S\)の\(X\)文字目までの文字を削除した文字列は明らかに\(T\)の部分列であって\(M\)より長い。
定義から\(M\)は「\(S\)の連続する先頭の何文字かを削った文字列であって、\(T\)の部分列(連続しているとは限らない)になっているもの」のうち長さが最大のものだったはずなので、これは矛盾。
よって、この問題の答えは\(|S| - |M|\)になるから、「\(S\)の連続する先頭の何文字かを削った文字列であって、\(T\)の部分列(連続しているとは限らない)になっているもの」を探せばよい。
これは貪欲法で後ろから文字を見ていけばすぐに分かる。
\(S\)を後ろから1文字ずつ\(T\)のある1文字と比較していけばいいので、全体の時間計算量は\(O(N)\)で抑えられ、制約下で充分高速である。
実装例は以下の通り。

N = int(input())
S = input()
T = input()

D_s = dict()
D_t = dict()
for i in range(N):
    if S[i] not in D_s:
        D_s[S[i]] = 1
    else:
        D_s[S[i]] += 1

    if T[i] not in D_t:
        D_t[T[i]] = 1
    else:
        D_t[T[i]] += 1

if D_s != D_t:
    print(-1)
else:
    answer = 0
    pivot = N - 1
    for i in range(N - 1, -1, -1):
        if T[i] == S[pivot]:
            pivot -= 1
    print(pivot + 1)
実装中は明らかにこれでいいだろうと思って作ってるけど、「これでいい理由」をちゃんと言語化するのは難しいと思った。
