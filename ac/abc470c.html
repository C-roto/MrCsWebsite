ABC470C Inc, Dec, Xor

問題文はこちらから。
数列全体を増減させながら、全体のビット単位XORを取る問題。

全体でビット単位XORを取るところと、クエリ2の処理をどうにかするところが壁。
前者はシンプルで、全体のビット単位XORを管理する変数を1つ用意し（\(answer\)とする）、数列の数値更新のたびに\(answer\)を\(answer \oplus (変更前の値) \oplus (変更後の値)\)とすればよい（ビット単位XORの交換性や結合性から、同じ値をビット単位XORするとビット単位XORの単位元である0に戻るからである）。
これは今回の桁数だとネックになるほどの時間はかからないはずである。

後者、つまりクエリ2の処理についてが厄介である。
数列全体を見て愚直に1ずつ引いていく、という処理はともすれば無駄に計算時間がかかってしまう気がする。
だが、よく考えてみるとクエリ2において引き算をする処理は全体で高々\(O(Q)\)回で押さえられるはずである。
クエリ全体のうち、クエリ1を行った回数を\(q\)回とする。この時、クエリ2によって数列の要素が引かれる回数も高々\(q\)回である。したがって、数列内で0である要素に触れず、かつ0である要素だけを的確に狙って引いていけば、足し算/引き算の回数もビット単位XORの回数も全体で高々\(2q\)回程度で押さえられる。
\(q \leqq Q\)であるから、これは\(O(Q)\)回と言っていい。
これであれば、「今0でない要素が何番目か？」を管理する集合を用意しておけば、それを使って上記の処理を高速に行える可能性がある。
そしてこれは実際以下のような実装の下で通る。
実装例は以下の通り。

N, Q = list(map(int,input().split()))
A = [ 0 for _ in range(N)]

answer = 0
nonzero = set()
for _ in range(Q):
    query = list(map(int,input().split()))
    if query[0] == 1:
        x = query[1] - 1
        if A[x] == 0:
            nonzero.add(x)
        answer ^= (A[x] ^ (A[x] + 1))
        A[x] += 1
    else:
        deletes = set()
        for nz in nonzero:
            answer ^= (A[nz] ^ (A[nz] - 1))
            A[nz] -= 1
            if A[nz] == 0:
                deletes.add(nz)
        for d in deletes:
            nonzero.discard(d)
    print(answer)
実は出題直後に後追いで解こうとして、解けなかった。
今回問題を見つめなおして「実は計算量が高々\(Q\)のオーダーで上から押さえられる」と気が付いた瞬間に解法を悟った。
何だこんなことだったのか……と思う反面、こんなことに気が付かない日もあるよね、と思ってしまった。納得、スッキリ。
