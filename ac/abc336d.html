ABC336D Pyramid

問題文はこちらから。 ピラミッドみたいになってる数列を削り出せるかを考える問題。

高さ\(X\)のピラミッド数列が作れるなら（余分に1回ずつ先頭と後ろを削り、各項から1を引けば）\(X-1\)のピラミッド数列が作れる。
また、これの対偶を取ると、高さ\(X-1\)のピラミッド数列が作れないなら、高さ\(X\)のピラミッド数列も作れないことが分かる。
よって、ピラミッド数列は「ある一定の値までは常に作れて、ある一定の値より大きくなると作れない」という性質を持つことが分かる。
この手の性質を持つものには二分探索が有効であるケースも多い。しかし今回はなかなかいいサーチ方法が思いつかない。先頭から順番に長さ\(X\)のピラミッド数列ができるかを愚直に調べると、恐らく\(O(XN)\)程度の時間がかかってしまうだろう。これは遅すぎる。

何故それほど時間がかかってしまうのかといえば、数列の「下り」側を調べるのが難しいからである。
便宜上、ピラミッド数列のうち前半の\(1,2,3,...,k-1,k\)を「上り」側、後半の\(k-1,k-2,...,2,1\)を「下り」側として扱う。
もし、ある数\(A_i\)までで\(X\)段の数列の「上り」（\(1,2,...,X-1,X\)）を作れる場合、次の数\(A_{i+1}\)を使って\(X+1\)段を実現できるかどうか調べるには、単に\(A_{i+1}とX+1\)の大小を調べれば良い。これなら\(O(N)\)程度で数列全体を走査できる。
一方で、下り側では素直に同じことを行えない。下りの\(X\)段が実現できている時、単にその1つ先だけを見て\(X+1\)段が構成できるかは不明であり、また段のすべてを再走査しないといけなくなる。このせいで効率が悪くなるのだ。

ここで発想を変える。上りと下りを同時に構成しようとするから難しいのであって、上りと下りを別々に考えるのはどうだろうか？
「\(A_i\)を終端とする上りであって、段数が最大のものは何段？」という問いは、先ほどと同様に考えれば解ける。実は、この問いの「上り」を「下り」に変えたものも、数列を逆順に走査すれば同様にすぐ答えが出せる。
そして、上りも下りも、\(X\)段が実現できれば\(X-1\)段が実現できるわけだから、今知りたいピラミッド数列の最大の段数は、「各\(A_i\)について先ほどの上りの最大段と下りの最大段のうち、最小の方を取る」という操作を繰り返して得られる最大値と一致する。
よって、数列を前からと後ろから、2回走査すれば答えが出せるので、時間計算量\(O(N)\)でこの問題を解くことができた。
実装例は以下の通り。

N = int(input())
A = list(map(int,input().split()))

nobori = [1]
kudari = [1]

tmp_nobori = 1
tmp_kudari = 1
for i in range(1, N):
    if tmp_nobori + 1 <= A[i]:
        tmp_nobori += 1
    else:
        tmp_nobori = A[i]
    nobori.append(tmp_nobori)

    if tmp_kudari + 1 <= A[N - 1 - i]:
        tmp_kudari += 1
    else:
        tmp_kudari = A[N - 1 - i]
    kudari.append(tmp_kudari)
kudari.reverse()

answer = 1
for i in range(N):
    if answer < min(nobori[i], kudari[i]):
        answer = min(nobori[i], kudari[i])

print(answer)
二分探索しやすい性質を持つことと、上りと下りを分けてよいということに気づくと解ける問題。
一見すると大変だが、なんか解けると気持ちいい。
