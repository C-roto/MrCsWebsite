ABC465D Pedometer

問題文はこちらから。
時計回りで歩く歩数が特定の数の倍数になるかを確かめる問題。

すべてのスタートとゴールの選び方は\(N(N-1)\)通りあるから、これをすべて試すのは非効率的。
「スタートとゴールを決める」に囚われると、高々定数倍程度の改善しかできず困ることになる。
発想を変えてみる。毎回スタートとゴールを決めて計算すると、「すでに計算した場所」まで多重に計算することになり、面倒だ。
こういう場合は「始点を一致させて累積和をとる」と、計算量を削減できるケースが多い。
具体的にはこういうことだ。休憩所\(t\)から\(s\)までの歩数は、休憩所\(1\)から\(s\)までの歩数から、\(1\)から\(t\)までの歩数を引くことによって求められる。
そして、休憩所\(1\)から\(k\)までの距離は、休憩所\(1からk-1\)までの距離に、\(k-1からk\)までの距離を加えればよく、これらは定数時間で計算可能だ。
\(s\)のほうが\(t\)より小さい場合は、\(s\)を\(s+N\)とみなして計算すればよく、結局全体として時間計算量は\(O(N)\)程度で済むはずだ。
あとは「\(M\)の倍数であるか」のチェックが必要だ。以下、休憩所\(1\)から休憩所\(k\)までの距離を\(S_{k}\)とする。
これは、\(i=1,2,...,N-1\)について、\(S_{i+1},S_{i+2},...,S_{i+N-1}\)の中に、\(M\)で割った余りが\(S_{i}\)と一致するものがいくつあるかを調べればよい。
ある2整数について、\(M\)で割った余りが等しいなら、その差は\(M\)の倍数になるからだ。
これは以下の実装例の通り、連想配列を使えば簡単に管理ができる。
実装例は以下の通り。

def dictplus(e, D):
    if e not in D:
        D[e] = 1
    else:
        D[e] += 1

N, M = list(map(int,input().split()))
A = list(map(int,input().split()))

S = [ 0 for _ in range(2 * N)]
for i in range(2 * N - 1):
    S[i + 1] += (A[i % N] + S[i]) % M

D = dict()
for i in range(N):
    dictplus(S[i], D)

answer = 0
answer += D[S[0]] - 1
for i in range(N - 1):
    D[S[i]] -= 1
    dictplus(S[i + N], D)
    answer += D[S[i + 1]] - 1
print(answer)
これも全然典型なのだが、いかんせん累積和とか苦手で結構見逃しがち。
累積和の関連分野でもある尺取り法とか結構ミスるし、勉強がいりますね。
