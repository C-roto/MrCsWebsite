ABC274D Robot Arms 2

問題文はこちらから。
ロボットアームをジャキンジャキンする問題。

問題の制約から、ロボットアームは縦か横にしか伸びず、しかも最初は必ず横に伸び、次に縦→横→縦→……と繰り返す感じになる。
また、制約上「縦の時にどう移動したか」は「横の時にどう移動したか」と全く無関係になる。
なので、縦の時にあり得る可能性を上手く検討すればよい。
ここで、各線分の長さ\(A_i\)は10以下だから、\(N \leqq 10^3\)回まで最大限操作してもあまり大きな値にならないことが分かる。なので、愚直にすべての移動を考えてもそんなに大変なことにはならなそうだ。
具体的にはx座標とy座標を記録しておく集合を設け、\(N\)回これらを走査する。
縦方向を考える時はy座標の集合を走査し、そこに記録されている座標(=その操作をする時点でアームが存在しうる場所)から\(±A_i\)だけ離れた地点をすべて列挙し、新たにy座標の集合として保存する。横の場合も同様にx座標の集合を変換する。
先ほど考えた通り、要素の数はそれほど莫大にはならない。時間計算量は\(O(max(A_i) \cdot N^2)\)程度で収まるはずで、これはこの制約下で十分高速である。
実装例は以下の通り。

def henkan(X, idx):
    res = set()
    for x in X:
        res.add(x + A[idx])
        res.add(x - A[idx])
    return res

N, x, y = list(map(int,input().split()))
A = list(map(int,input().split()))

# A[i]の制約とNの制約から、扱う座標の絶対値は10^4以下の値にしかならない
# 1回の変換過程で2*10^4+1個以上の入力、出力は出てこないので、見た目より高速になる
# 端的に言えばO(N*(N*max(A[i])))程度で処理出来て、これはそんなに遅くない
tate = set([A[0]])
yoko = set([0])

# 縦の動きは横の動きに影響を与えない、逆もしかり
for i in range(1, N):
    if i % 2 == 0:
        tate = henkan(tate, i)
    else:
        yoko = henkan(yoko, i)

# 全部の移動が終わった後のX座標とy座標を見る
if x in tate and y in yoko:
    print('Yes')
else:
    print('No')
一見すると総当たりがきつそうに見えるけど、意外と握りつぶせるし、そもそも幅が小さいというのは面白い。
