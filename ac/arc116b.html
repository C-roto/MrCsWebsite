ARC116B Products of Min-Max

問題文はこちらから。
すべての部分列の最大値と最小値の積の総和を求める問題。

部分列については連続でなくても良いので、順番は関係ない。
よって、最大最小を考えやすくするために、昇順でソートができていると仮定してよい。
以降、数列\(A\)は昇順でソートされているものとする。

数列\(A\)の適当な2つの項を選ぶと、それを両端(つまり最小値と最大値)とする部分列ができる。
これを全部カウントすると組み合わせの数だけ計算せねばならず、制限時間以内には間に合わない。
こういう時は端のうちどちらかを固定することを考える。
例えば、\(min(B)=A_i\)となるような組についての総和はどうなるだろうか？
今、数列\(A\)はソートされているという前提であるから、\(A_i\)以前の項については考えなくて良い。
\(A_i\)以降の項については……
・\(max(B)=A_i\)となるのは、\((A_i)\)のみなので1通り
・\(max(B)=A_j \hspace{0.5em} (j>i)\)となるのは、\(i < k < j\)を満たす\(a_k\)を含めるかどうかなので\(2^{j-1}\)通り
なので、結局\(min(B)=A_i\)となるような組に関する総和は
\({A_i}^2 + A_i \cdot \sum_{j=1}^{N-i} 2^{j-1}A_i+j\)
となる。これを\(i=1,2,...,N\)に関して足せばよい(ただし\(i=N\)のときは\(\sum\)の部分は0と約束する)。

ここで\(S_i = \sum_{j=1}^{N-i} 2^{j-1}A_i+j\)とおくと、\(S_{i+1}= (S_i - A_i) \div 2\)で計算できることが分かるので、最初に\(S_1\)を求めておけば、後はそこから項を引いて2で割る操作を繰り返すことで各\(S_i\)を簡単に求めることができる。
よって、各\(i=1,2,..,N\)に対し、\({A_i}^2 + A_iS_i\)は（modを取る操作を度外視すると）\(S_1\)を求めるのだけ時間計算量\(O(N)\)が掛かり、後は定数時間で処理ができる。
なるべく大きい数を扱わないためにmodを取る操作はガンガン途中で挟めばよいが、2で割る操作はmod998244353においては499122177を掛ける操作と同一視できることに注意して、そのように書く。逆元があるってサイコーだ。
結局最初に\(A\)をソートするところがネックになり、全体の時間計算量は\(O(Nlog_{}{N})\)になる。これは制約下においては十分高速である。
実装例は以下の通り。

N = int(input())
A = list(map(int,input().split()))
A.sort()

mod = 998244353

pow_twos = [ 1 for _ in range(N + 1)]
for i in range(1, N + 1):
    pow_twos[i] = (pow_twos[i - 1] * 2) % mod

maximumsum = 0
for i in range(1, N):
    maximumsum += (A[i] * pow_twos[i - 1]) % mod
two_rev = 499122177
answer = 0
for i in range(N - 1):
    answer += (((A[i] ** 2) % mod) + (A[i] * maximumsum) % mod) % mod
    maximumsum -= A[i + 1]
    if maximumsum < 0:
        maximumsum += mod
    maximumsum *= two_rev
    maximumsum %= mod

answer += (A[-1] ** 2) % mod

print(answer % mod)
「如何に計算量を減らすか」ということにすべてが掛かっているように思える。
特に、組み合わせの問題に帰着できると分かってからは、「どうやって\({N \choose 2}\)通りを見ずに立式するか」という問題に落ちつくわけで、それは「どうやって再利用できる部分を発見するか」ということでもあると思う。
これに限らず、結構「再利用できるところを見つける」ってのは大事だよなと思う。
