ABC127D Integer Cards

問題文はこちらから。
整数の書かれたカードを書き換える問題。

カードの並び順は関係ないので、今後のことを考えてソートする。
そして実は、クエリの適用順も与えられた順番でなくとも全く問題ない。
クエリ順をめちゃくちゃにしても、最終的にどのカードが何の数字になったのかにさえ注目すれば、元のクエリ順で得られる結果と同じものが得られるからだ（逆にどんなにクエリ順をめちゃくちゃにしても、元のクエリ順でそれを実現できる）。
よって、クエリも\(C\)の大きさ順でソートしておく。

後は\(A\)とクエリをそれぞれ先頭から見ていき、変えた方が得になるなら変えていく操作を続ければよい。
→なるべく変更後の列と変更前の列とで、各要素の絶対値が大きくなるように貪欲に変えていけばよい（もし貪欲な手順以外で最良の結果が得られる場合、その部分を貪欲手順と同一に変えたものの方が明らかに良い結果になる）。
変えた方が損になる場合、以降はどこを変えても損になるのが確定しているから、そこで操作を打ち切る。
各カードについて高々1回ずつしか操作されないことと、カードの枚数が多いときはクエリの数しかループが回らないことから、全体の時間計算量は\(O(min(N + sum(B)))\)程度で収まり、制約下では充分に高速だろう。
実装例は以下の通り。

N, M = list(map(int,input().split()))
A = list(map(int,input().split()))
query = []
for _ in range(M):
    query.append(list(map(int,input().split())))

A.sort()
query.sort(key = lambda x: -x[1])

idx = 0
for b, c in query:
    ng_flag = False
    for _ in range(b):
        if idx == N:
            ng_flag = True
            break
        
        if A[idx] < c:
            A[idx] = c
            idx += 1
        else:
            ng_flag = True
            break
    if ng_flag:
        break

print(sum(A))
流石に初期の問題だけあってそれほど大変でもないか……。
一方で初期の問題でも全然解けない奴はあるので舐めてはいけない気もする。
