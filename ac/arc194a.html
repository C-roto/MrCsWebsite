ARC194A Operations on a Stack

問題文はこちらから。
スタックに入れるか、スタックから出すかを繰り返して値を大きくする問題。

愚直な実験をすると失敗する。その場で取れる最大値を取っていく、みたいなのはあまりうまくいかない。
各\(i\)に対して2種類の選択ができるので、上手く選び方を考えるとDPで結果を握りつぶせるような気がしてくる。が、なかなかうまくいかない。「スタックが空の時はポップできない」みたいな制約が邪魔をしてくる。
こういう場合はある場所に遷移してくるパターンにどういうものがあるかを冷静に考えてみる。ちゃんと遷移を考えるのだ。
\(dp_i\)を「\(i\)番目までの要素を見て操作を終えたときの、スタック中の要素の総和の最大値」としたとき、\(dp_i\)への遷移は以下の通りだ。
・\(dp_{i-1} + A_i\)（\(i-1\)番目まで見たときの最大値に、\(A_i\)）を加える）
・\(max(dp_{i-2},dp{i-4},...)\)（\(i-2,i-4,...\)番目までの最大値。それ以降から\(i\)番目までの要素はpushとpopを繰り返してすべてなかったことにする）
この2つであって大きい方が\(dp_i\)である。
下の遷移は分かりにくいものの、結局、その要素を取るか取らないかに帰着していて、「取らない」のパターンをすべて列挙しているに過ぎない。思いつきにくいが、僕は遷移のグラフを描いて一旦配るdp的に見た後、受け取るdpの方が分かりやすいと思ってこう書いている。
よって、偶数添え字のうちでそれまでの最大値と、奇数添え字のうちでそれまでの最大値を管理する変数でも用意しておけば、下の遷移は定数時間で計算できる。上の遷移は言うまでもなかろう。
というわけで、dpの各回は定数時間で計算でき、それが\(N\)回行われるので、dp全体は時間計算量\(O(N)\)で処理できる。
求める答えは、上記と同様に考えると\(dp_{N},dp_{N-2},dp_{N-4},...\)のうちで最大のものである。
よって、全体の時間計算量は\(O(N)\)で、この制約下では十分高速である。実装例は以下の通り。

N = int(input())
A = list(map(int,input().split()))
dp = [ 0 for _ in range(N + 1)]
A.insert(0, 0)

odd_max = A[1]
even_max = 0
dp[1] = A[1]
for i in range(2, N + 1):
    if i % 2 == 0:
        dp[i] = max(dp[i - 1] + A[i], even_max)
        if dp[i] > even_max:
            even_max = dp[i]
    else:
        dp[i] = max(dp[i - 1] + A[i], odd_max)
        if dp[i] > odd_max:
            odd_max = dp[i]

pivot = N
answer = -1 * 10 ** 50
while pivot >= 0:
    if answer < dp[pivot]:
        answer = dp[pivot]
    pivot -= 2
print(answer)
終わってみたら別に大した問題じゃないのだけれど、dpの遷移が見えなくて色々考えてしまった。反省。
