ARC120B Uniformly Distributed

問題文はこちらから。 赤青に塗り分けたチェス盤を左上から右下まで、赤色の個数が同じように辿れるよう塗る問題。

マスを赤/青で塗るという2通りがあるな～動的計画法とかで回すのかな～と思っていたが、あまりうまくいかなそうに思える。
各マスに対して保持しておくべき情報を上手く乗せるのがキツい。そこまでに通った赤マス/青マス/無色マスの情報を乗せるとパンクするし、仮に乗せられたとして上手い使い方も見えない。

もっと別の見方をしよう。
通りうるすべてのルートは、\({H + W \choose H}\)通りと、非常に莫大な個数になる。
すると「任意のルートを通っても赤マスと青マスの数が変わらない」ということを、全パターン総当たりで調べるのは難しい。一方で、ある2つのルートに関して見比べることは難しくない。
上手い2つのルートを見て、その2ルートで赤/青の個数が等しくなるか否かを考えてみる。
今回考えたのは、「殆どが同じで1か所だけが違う」という2つのルートだ。
つまり、以下のような2つのルートを考える。
・\((1,1)→(a,b)→…→(i,j)→(i+1, j) →(i+1,j+1)→…→(H,W)\)
・\((1,1)→(a,b)→…→(i,j)→(i, j+1) →(i+1,j+1)→…→(H,W)\)
あるルートにおいて右→下と進んでいる箇所を、下→右と動いてみるルートということだ。
この場合、マス\((i+1,j)\)とマス\((i,j+1)\)だけが異なり、他のマスはすべて同じルートなわけだから、2つのルートで赤と青が同じ数だけあるかどうかは、マス\((i+1,j)\)とマス\((i,j+1)\)の色にのみ依存する。
この2マスが同じ色ならオーケー、違えば不可能。
要するに、「右上と左下で隣り合う2マスが同色ならこの2ルートにおける赤マスの数は等しいし、そうでないなら違う」ということが分かる。
これを繰り返し適用すると、「右上から左下に伸びる各斜めの列について、その列がすべて同色ならその列を通るすべてのルートについて赤マスの数は等しいし、そうでないなら少なくとも2つのルートでは赤マスの数が違う」ということが分かる。
任意のルートはあらゆる斜めの列のいずれかを通るから、実質的に「その列を通るすべてのルートについて」の部分を省略しても問題ない。
「そうでないなら違う」という部分から、必要十分性も分かる。

もう少しきちんとした言葉で整理しよう。
任意の2マス(p,q)と(s,t)について、「p+q=s+tであるならばマス(p,q)とマス(s,t)が同色である」ときに、かつその時に限って「任意のルートにおける赤マスの個数が等しい」と言える。
要するに、「p+q=s+tであるならばマス(p,q)とマス(s,t)が同色である」ように盤面を塗る方法がどれだけあるか、がこの問題の肝になるのだ。
これは以下のように場合分けができる。
・もしp+q=s+tなのにマス(p,q)とマス(s,t)が異なる色で塗られているようなp,q,s,tがあるとき →0通り。 ・そのようなマスがない場合 →p+q=rとなるようなマス(p,q)の集合であって、既に赤か青で塗られているものがある場合 →→その集合に含まれる無色のマスは、すでに塗られているマスと同色になるしかないので1通り →p+q=rとなるようなマス(p,q)の集合であって、既に赤か青で塗られているものがない場合 →→その集合はすべて無色であり、集合内のすべてのマスを赤もしくは青で塗る2通りがある よって、各場合について何通りあるか出して、それらをすべて掛け合わせればよい。
時間計算量は各マスを1度ずつ走査する部分がネックで、\(O(HW)\)になる。これは制約下で十分高速である。
実装例は以下の通り。

H, W = list(map(int,input().split()))
S = []
for _ in range(H):
    S.append(input())
mod = 998244353

answer = 1
# 右上から左下への斜め列に異なる色があれば上手く塗れない
# そうでないならOK、未塗りのマスがあればそのマス
for i in range(H + W - 1):
    diagonal = set()
    # マスのx座標とy座標の和が一定＝同じ斜め列にある内容をピックアップ
    for j in range(i + 1):
        if H - 1 >= i - j >= 0 and W - 1 >= j >= 0:
            diagonal.add(S[i - j][j])
    # 今調べている斜め列が無色のみ？
    if "." in diagonal and "R" not in diagonal and "B" not in diagonal:
        answer *= 2
        answer %= mod
    # 今調べている斜め列に2色同時に出てきている？
    if "R" in diagonal and "B" in diagonal:
        answer = 0

print(answer % mod)
愚かなので1回modを取り損ねてWAになった。悲しいね。
これも高校数学って感じで、特にアルゴリズム的な発想は新しく使わなかった気もする。
結構ひねりがいというか、考えがいのある良い問題だと感じる。
