ABC344D String Bags

問題文はこちらから。
バッグの中から文字列を取り出すよ！ なんだそれ～！ な問題

貪欲法は上手くいかない。
極端な例を考えてみると分かる。前の方の6つのバッグからa,b,c,d,e,fを取り出すより、後ろの方の1つのバッグに入っているabcdefを取り出した方が明らかにコストは低い。
こういう、前から順に選択肢を見て、その選択肢の中から択一して結果を見る、というタイプの問題には動的計画法が効く。具体的な手順を握りつぶして、コストだけを拾うという方針に特化するわけだ。
この問題については、正直ここまでわかれば後は愚直に実装するだけ。
DPテーブルの内容は「\(i\)番目までのかばんを見たときに、Tの\(j\)文字目までと一致する文字列を作るのにかかる最小のコスト」を保持しておけばよい。
遷移は「どの文字も拾わない場合」と、「各文字を（拾える場合に）拾った場合」についてのみ考えればよい。
実装例は以下の通り（コメントとか書いておけばよかった……何か見づらい）。

T = input()
N = int(input())

dp = [ [ 1000 for _ in range(len(T) + 1)] for __ in range(N + 1)]
for i in range(N + 1):
    dp[i][0] = 0

for i in range(1, N + 1):
    S = list(input().split())
    A = int(S[0])
    for j in range(len(T) + 1):
        dp[i][j] = min(dp[i][j], dp[i - 1][j])
        for k in range(1, A + 1):
            ok_flag = True
            for l in range(len(S[k])):
                if j + l >= len(T) or T[j + l] != S[k][l]:
                    ok_flag = False
            if ok_flag:
                dp[i][j + len(S[k])] = min(dp[i][j + len(S[k])], dp[i - 1][j] + 1)

if dp[-1][-1] == 1000:
    print(-1)
else:
    print(dp[-1][-1])
言うことがあんまりない。
シンプルな問題というのも悪いわけではないと思う。
