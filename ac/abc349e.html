ABC349E Weighted Tic-Tac-Toe

問題文はこちらから。
盤面に重みが付いた三目並べの勝者を求めるゲーム。

盤面サイズとマスの状態数が非常に小さいので、あり得る盤面全体の状態も少ない。
よって、あり得る状態を全探索するという手段を取りやすい。

今回中心となるアイデアは「再帰的に勝敗を求める」というものになる。
ある盤面において、その手番のプレイヤーが勝つ方法があるかを知るにはどうすればよいだろう？
これはすべての打ちうるところに手を打ってみて、その先のすべての盤面について再び勝敗を求める、ということをやってみるのが良いだろう。
いつか勝敗が付く(これは認めることにする)わけなので、勝敗が付いたタイミングから勝敗の情報を遡っていくと、今勝敗を求めたい盤面から打てるあらゆる手について、それを打った先の盤面の勝敗が決まる。
もしその中に、打つことで自分が勝つ盤面があるなら、そうなるように手を打てば勝てるので、現在の盤面は手番プレイヤーの勝ちになる。そうでないなら、どのように手を打っても手番プレイヤーは負けるので、現在の盤面は手番プレイヤーでない方の勝ちになる。

上記の発想を中心として、以下のような関数\(\g\)を用意する。
・まず、ある盤面が与えられた際に、勝敗が付いていれば勝者を出力し、付いていなければ未確定であることを返す関数\(f\)を用意する

・盤面と手番プレイヤーが与えられたときに、最終的な勝者を返す再帰関数\(g\)を以下のように定義する(与えられた盤面を\(B\)とする)
→もし\(f(B)\)が勝者を返して来たら、\(g(B)=f(B)\)とする。
→そうでないなら、\(B\)から手を打って遷移できる盤面\(C_1,C_2,...,C_k\)について、\(g(C_1),g(C_2),...,g(C_k)\)をそれぞれ再帰的に計算する。この中に手番プレイヤーを返してくるものがあれば、\(g(B)\)の値は手番プレイヤーであるし、そうでなければ\(g(B)\)は手番プレイヤーでない方のプレイヤーになる。

再帰関数が各盤面に対して一意に、かつ常に値が定まることには本来証明が必要だが、今回は省略する（盤面がループしないし、高橋君と青木君が同時に縦横斜めをそろえることもないし、盤面の個数は有限個しかないし、必ず値が確定する盤面が存在する……あたりを厳密に言えばいいか）。
関数\(f\)の用意が大変だが、これは実装例を見てもらった方が早いと思う。定義に従って愚直に書いているだけだ。

ともあれ、あり得る盤面を全部一度ずつ舐めてみることで最終的な勝者も分かるため、盤面の一辺を\(N\)として\(\omega(N^2 (N^2)!)\)程度はかかる。
実装例だと多分forループ内のlist生成がネックで、全体の時間計算量は\(O(N^4 (N^2)!)\)程度になると思うが、制約下ではこのオーダーでも十分高速である。
実装例は以下の通り。

# 高橋君をプレイヤー0,青木君をプレイヤー1とする
# 以降、「勝者を返す」とは「勝者のプレイヤー番号を返す」という意味である

# 盤面について、[A[0][0], A[0][1], A[0][2], A[1][0], A[1][1], A[1][2], A[2][0], A[2][1], A[2][2]]の順に一列で受け取る

# 状態を与えられたらある色がすべて揃っているかを確かめる関数
# 揃っていればその色のプレイヤー番号を、そうでなければ-1を返す
def liner(x):
    # 縦
    for i in range(0, 9, 3):
        if x[i] == x[i + 1] and x[i + 1] == x[i + 2] and x[i] != ".":
            return int(x[i])
    # 横
    for i in range(3):
        if x[i] == x[i + 3] and x[i + 3] == x[i + 6] and x[i] != ".":
            return int(x[i])
    # 斜め
    if x[0] == x[4] and x[4] == x[8] and x[0] != ".":
        return int(x[0])
    if x[2] == x[4] and x[4] == x[6] and x[2] != ".":
        return int(x[2])

    # 揃っていない場合
    return -1

# 状態と盤面の得点が与えられたとき、勝者が確定していればそれを返す関数
# 勝者未確定の場合は-1を返す
def winner(x, Board):
    p = liner(x)

    # 一列に揃っている色があるなら返す
    if p != -1:
        return p

    # 埋まっていないマスがあるなら(揃っている色がないので)勝者未確定
    if "." in x:
        return -1

    # 全マスが埋まっている状態なら得点計算をする
    t = 0
    a = 0
    for i in range(9):
        if x[i] == "0":
            t += Board[i]
        else:
            a += Board[i]

    # 得点をより取っている方が勝者
    if t > a:
        return 0
    else:
        return 1

# ある盤面における勝者を再帰的に求める関数
# staが盤面の状態、turnはターンプレイヤーのプレイヤー番号
def total_winner(sta, turn):
    p = winner(sta, A)
    # 勝者が確定しているならその勝者を返す
    if p != -1:
        return p

    # 打てうる手を打った時の勝敗を見て、現在の盤面の勝者を決めて返す
    for i in range(9):
        # そもそも手が打てて、かつ今がプレイヤーxのターンで、かつ次の手はxが勝者か？
        # そうならこの盤面もプレイヤーxが勝者
        if sta[i] == "." and total_winner(sta[:i] + [str(turn)] + sta[i+1:], (turn + 1) % 2) == turn:
            return turn

    # 次の手をどこに打っても自分が勝てないなら、相手の番号を返す
    return (turn + 1) % 2

# 盤面情報の受け取り（上→左順で一列に受け取る）
A = []
for i in range(3):
    a = list(map(int,input().split()))
    A.extend(a)

# 最初の盤面から行けるすべての盤面を再帰的に辿って、最初の盤面の勝者を求める
# 2色以上が並んでいる状態には辿り着かない
if total_winner(["." for _ in range(9)], 0) == 0:
    print("Takahashi")
else:
    print("Aoki")
大昔にマンカラで人間と戦ってくれるプログラムを書いたことがあったが、そのときよりも圧倒的に小さい盤面で、再帰というまた別の形の処理を使って書くことになった。
やってることはゲーム木に対して深さ優先探索をしているだけとも言える。
盤面が小さいのでこちらの方が単純だし、こっちは確実に勝てる解を探すのに対して、あちらは良さそうな方を選ぶという違いはあるけれど、再帰を組むのは割と大変でちょっと時間がかかった。
