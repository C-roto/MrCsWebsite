ABC269E Last Rook

問題文はこちらから。
盤面に大量のルークが置かれており、最後に唯一ルークを置ける箇所を探す問題。

質問は20回までしかできない。
また、「長方形範囲を指定してその中にルークがいくつあるか」を聞くという性質上、「ここにルークが置けますか？」とは聞けないのが厄介。
ここはまず、最終形を想像するところから始めよう。つまり、「最後のルークが置けたとしたら盤面はどうなっているのか？」を想像する。
この時、各列各行に、ただ1つずつルークが存在しているはずだ。
ここからルークを1つ除いてみる。すると、ただ1つどこかの列と、ただ1つどこかの行にルークが置かれていない状態になっている。これが問題で与えられる盤面、つまり「最後のルークが置かれる前の盤面」である。
とすれば、ルークが置かれていない行と列の番号を特定できれば、その行と列の交点こそが最後のルークを置くべき位置になるはずである。

長方形領域を活用して、どの行にルークが置かれていないかを調べる方法はないだろうか？
行だけに注目する場合、長方形領域の最右列と最左列は、盤面のそれらと一致させてよい。
そうして考えてみると、例えば「? 1 3 1 N」のような指示を出すことで、「1行目から3行目までの間にルークは何個ありますか？」という問いを発することができる。
このような行に関する質問について、答えは必ず、確認している行数と一致するか、またはそれより1少ない値のいずれかになる（2以上少ない場合は、2行以上ルークが置かれていないマスが存在することになってしまうし、確認中の行数より多いとルークが2つ以上置かれている行が存在してしまう）。
もし確認している行数と一致する値が返ってきたなら、今調べた範囲に新しくルークを置けるところがないから、別の範囲を探せばよい。もし1小さい値が返ってくれば、その中に答えの行があるはずだ。
こうした探索を効率よくやろうと思うと、自然に二分探索が思いつくのではないだろうか。特に今回は「求める行\(i\)がただ一か所ある」という条件なので、範囲を二分探索で狭めていけば上手く行くことは直観的にも分かりやすい。
行に関して、二分探索で条件を満たす位置で答えとなる行\(X\)を調べ、列に関しても同じように二分探索で答えとなる列\(Y\)を調べれば、答えとなるマスは\(上からX行目、左からY列目\)だと分かるので、「! X Y」と返してやれば良い。
計算回数だが、マスの縦横幅は最大でも\(10^3\)であるから、\(log_2{10^3} < 9.94 < 10\)であり、行と列の二分探索は各10回以下で済む。これならギリギリ20回に間に合い、また計算量もおよそ\(O(log{N})\)程度で済むので十分高速だ。
実装例は以下の通り。

def binarysearch(x, y, ty):
    while x != y:
        m = (x + y) // 2
        if ty == 0:
            print("?", x, m, 1, N)
        else:
            print("?", 1, N, x, m)
        t = int(input())
        if t < m - (x - 1):
            y = m
        else:
            x = m + 1
    return x

N = int(input())

A = 1
B = N
C = 1
D = N

X = binarysearch(A, B, 0)
Y = binarysearch(C, D, 1)

print("!", X, Y)
\(log_2{10^3}\)の値はググって調べたが、よく考えたら\(3\frac{1}{log_{10}{2}}\)なんだから普通に計算すればよかったなあと反省。\(log_{10}{2} > 0.3\)ぐらいの雑な見積もりでも\(10 > log_2{10^3}\)が言えるので、今回の問題なら十分だった。
問題そのものは「あえて縦横の自由度を少し減らして二分探索を思いつけるか？」が鍵だったように思う。
あと二分探索のアルゴリズムをよく書き間違えて無限ループさせてしまう身としては、実装の方が気を遣う気もする。今回は結構回数ギリギリなので、なおのことちゃんと考えないといけない（適当なとこまで調べて後は適当に総当たりするとオーバーする）わけである。基礎基本は大事。
