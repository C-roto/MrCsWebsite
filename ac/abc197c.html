ABC197C ORXOR

問題文はこちらから。
区間のORを取って、出た値のXORを取る問題。

どう区間を分けたら最小になるのかを考えてもあんまり見えない。
制約の小ささから、全パターン試せるのではないかと考えて分けてみるのが速そうだ。
「\(i\)項目が区間の右端となるかどうか」を見れば、あらゆる区間分割に対応できると気付けば、これは結局「この数は区間の右端か？」への答えとしてあり得るものを全列挙すればよいことになる。
というわけで、これはビット全探索に落ち着く。実装例ではitertools.productで全列挙したが、本質的には同じだ。
与えられる数列の最終項は必ず区間の右端だから、それ以外のN-1個の値に関して全探索を試みればよい。
実装例は以下の通り。

import itertools

N = int(input())
A = list(map(int,input().split()))

# 区間端の選び方は2^N通り=2000000以下通りしかない
# 列挙して全探索すればよい(bit全探索)
C = itertools.product([0, 1], repeat= (N - 1))

answer = 10 ** 100
first_one = True
for c in C:
    ORs = []
    tmp = 0
    for p in range(len(c)):
        tmp = tmp | A[p]
        if c[p] == 1:
            ORs.append(tmp)
            tmp = 0
    tmp = tmp | A[-1]
    ORs.append(tmp)
    
    tmp_2 = 0
    for r in ORs:
        tmp_2 = tmp_2 ^ r
    if answer > tmp_2:
        answer = tmp_2

print(answer)
と考えたところで、XORの結合性やYes/Noを考えるという問いの性質から、DPでも解ける可能性に気が付く。
公式解説に実際それで解いているユーザー解説があったが、最悪計算量は結局愚直に解くのと変わらないっぽい。
あんま上手く結果を握りつぶせないってことなんだろうか……。
