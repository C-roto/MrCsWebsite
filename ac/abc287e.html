ABC287E Karuta

問題文はこちらから。
与えられた各単語について、他の文字列と先頭の文字数がどれくらい一致してるかを確かめる問題。

実は半年ほど前に別の解き方で解いていたのだが、今回AtCoder Novistepsからこの問題がTrieと呼ばれるデータ構造に強く関係していることを知ったので、折角ならとTrieを使って問題を解いてみることにした。
ネットを探せばNodeクラスを定義して、そのNodeクラスからTrieを構築する方法も載っていたが、辞書型を使っても同じことが実現できるのでは？ と考え、今回は辞書型を用いて実装した（色々な情報を盛るのはNodeクラスを別に定義したほうが明らかに楽なので、今後はそっちを用いるつもりだ。あくまで練習）。
さて、Trieを使うことで「ある文字列をprefixに持つ文字列が存在するか？」は簡単に調べられるようになる。 ある文字列\(S_k\)について、\(LCP(S_k,s_i)=0(1 \leqq k \leqq N,k \neq i)\)となるとしよう。つまり、\(S_k\)はどの文字列とも先頭の何文字も共有しないとする。
これがどういう状況なのか考えてみる。すると、\(S_k\)の先頭を1文字ずつ伸ばしながらTrieをたどって行くと、一度も分岐に遭遇せず、終端に辿り着いても自分しかいないような状況だと分かる。
逆に、辿っていく途中でどこかに分岐があった場合、そこから別の文字へと伸びる辺が存在することになり、自分以外で先頭からそこまでの文字が一致する別の文字列が存在することが保証される。
また終端に自分以外がいる場合、同じ単語が2回入力されたということになり、これは確かに自分以外で自分と全く同じ先頭文字を持つことになる。
よって、各単語について、各ノードにおいて分岐があるかを調べつつTrieを下っていき、終端に辿り着いたら、同じ終端を持つ単語が複数ないかをチェックしておく、という方法が正当になる。
時間計算量は各文字列の長さの総和を\(sum(S)\)として\(O(sum(S))\)で押さえられて、制約下で高速である。
実装例は以下の通り。

class Trie:
    def __init__(self):
        self.Nodes = dict()
        self.word_id = 1

    def insert(self, word : str):
        nodes = self.Nodes
        for c in word:
            if c not in nodes:
                nodes[c] = dict()
            nodes = nodes[c]
        if "$" in nodes:
            nodes["$"].add(self.word_id)
        else:
            nodes["$"] = set([self.word_id])
        self.word_id += 1

    def search(self, word : str):
        nodes = self.Nodes
        for c in word:
            if c not in nodes:
                return False
            nodes = nodes[c]
        if "$" in nodes:
            return True
        return False

    def has_branch(self, pref : str):
        res = 0
        now = 0
        nodes = self.Nodes
        for c in pref:
            if len(nodes) > 1:
                res = now
            now += 1
            nodes = nodes[c]
        if len(nodes) > 1 or len(nodes["$"]) > 1:
            res = now
        return res

trie = Trie()

N = int(input())
S = []
for _ in range(N):
    s = input()
    trie.insert(s)
    S.append(s)

for i in range(N):
    print(trie.has_branch(S[i]))
Trieは構造自体はとても単純だし、ノードの構築も「なければ作る」でいいし、ノード検索も「なければ終わり」で良いので、楽だ。その割に応用の幅も広そうで、なかなか興味深い。
