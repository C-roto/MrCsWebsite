ARC324D Square Permutation

問題文はこちらから。
与えられた数列を並べ替えて作れる平方数の数を数える問題。

並べ替えを実際にやると最大で\(13!=6227020800\)通りになる。また、平方数の判定方法は（私が知る限り）素因数分解を間に挟まないといけないので、愚直にやると各調べる数の平方根までは調べる必要がある。
それを高速化する方針は思いつかない。
逆に、平方数の側を全列挙して、それが上手くいくかどうかを調べる方が楽そうだ。これなら、\(\sqrt{10^{13}} = \sqrt{10} \cdot 10^6 \leqq 4 \cdot 10^6\)個程度を調べるだけなので、1回の判定時間が短ければ充分ワークするだろう。

ある平方数\(Q\)が与えれらたとき、問題の数列\(S\)の全要素を使って、その平方数を作ることができるか調べる方法を考える。
・0以外の数字については、\(Q\)と\(S\)の中でその個数が異なる数字があると、その時点でダメだ。
・0については、\(Q\)に含まれている数が\(S\)に含まれている数より真に多かったときはダメで、そうでなければ\(S\)の余分な0を先頭に回せば問題ない。
というわけで、上記の2点を判定するアルゴリズムを書けばよい。配列(Pythonならリスト)とか連想配列みたいなものを使えば充分に作れる。
この判定は各平方数に含まれる数字の個数より多い回数回ることはないはずなので、時間計算量\(O(N)\)で回ると考えてよいはずだ。

よって、全体としては
・平方数を列挙する
・列挙した平方数をそれぞれ処理する
あたりを考慮して、時間計算量\(O(\sqrt{10^N} \cdot N)\)程度で収まるはずだ。これは制約下においては充分高速であろう。
実装例は以下の通り。

N = int(input())
S = input()

D = [0 for _ in range(10)]
for i in range(N):
    D[int(S[i])] += 1

answer = 0
for i in range(3162278 + 1):
    res = [0 for _ in range(10)]
    check = i ** 2
    if check == 0:
        res[0] = 1
    while check > 0:
        res[check % 10] += 1
        check //= 10

    ok_flag = True
    for j in range(10):
        if j == 0 and D[j] < res[j]:
            ok_flag = False
            break
        if j != 0 and D[j] != res[j]:
            ok_flag = False
            break

    if ok_flag:
        answer += 1

print(answer)
手元環境だと実行に3~4秒程度かかるが、Atcoderのジャッジでは300~400ms前後で終わったらしい。
環境の差？ どういう要因があるんだろうか。
