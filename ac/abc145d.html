ABC145D Knight

問題文はこちらから。
特定のマスに移動するためのナイトの移動方法の数を調べる問題。

ああはいはいDPですね～とか思ってたら、制約上全マスを舐めている余裕がないことに気が付く。安易な決めつけはよろしくないね。
つまりもっと効率の良い計算方法があるというわけだ。
\((0,0)\)からの遷移の過程を書いてみると、とりあえずマス\((i,j)\)に到達できる必要条件として\(i+j\)が3の倍数であることや、\(min(i,j)\)が\(\frac{i+j}{3}\)以上であることが分かる（そして実は十分でもある）。
以下、\(X+Y\)は3で割り切れ、\(min(X,Y)\)が\(\frac{X+Y}{3}\)以上であると仮定して進めていく。
遷移図を書いてにらんでみると、見たことのある図形と同じ形をしていることに気が付くのではなかろうか。そう、パスカルの三角形と呼ばれるアレである。
というわけで\(Z=\frac{X+Y}{3}\)とすると、答えは\(\binom{Z}{min(X, Y) - Z}\)と書けることが分かる。
\(Z\)の値は最大でも\(2 \cdot 10^6\)程度なので、愚直に値を掛け算しながらmodを取って、その逆元を1つずつ見つけていくという方針で\(\binom{Z}{min(X, Y) - Z} (mod 10^9+7)\)は問題なく計算できる。
全体の時間計算量は逆元を求める部分か、もしくは階乗を計算する部分になるだろうから、\(O(X+Y+\log_{}{mod})\)程度で押さえられ、これは制約下で十分高速だろう。
実装例は以下の通り。

X, Y = list(map(int,input().split()))
mod = 1000000007

def modfrac(x):
    res = 1
    for i in range(1, x + 1):
        res *= i
        res %= mod
    return res % mod

def modintrev(x):
    doubling = x
    p = mod - 2
    res = 1
    while p != 0:
        if p & 1 == 1:
            res *= doubling
            res %= mod
        p = p >> 1
        doubling = doubling ** 2
        doubling %= mod
    return res % mod

def modintcomb(N, K):
    return (modfrac(N) * modintrev(modfrac(K)) * modintrev(modfrac(N - K))) % mod

if (X + Y) % 3 != 0:
    print(0)
elif min(X, Y) < (X + Y) // 3:
    print(0)
else:
    # X + Y // 3 = Zとすると、答えはcomb(Z, min(X, Y) - Z)になる
    Z = (X + Y) // 3
    print(modintcomb(Z, min(X, Y) - Z))
考えてみると「チェス盤上にパスカルの三角形が描ける」って事実は面白い。ないはずのものがそこに見えるっていうのは、趣すらあるかもしれない。

不思議なもので、DPだなと思うと思考がそっち方向に誘導される。
「下を再帰的に求められるな～」というのは嘘ではないけど、効率的ではないという事実に気が付くのにだいぶ時間がかかってしまった。
