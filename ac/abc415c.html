ABC415 Mixture

問題文はこちら。

なんとなくAtcoderを始めた僕が、その後もAtcoderを続ける動機になった問題。
今思えば別に難問でもないし、典型の1つにすぎないのだけれど、「問題を抽象化して見方を変える」という体験が学び始めの僕に与えた衝撃は大きい。

公式解説に書いてあることがすべてなのだが、自分の言葉で整理してみる。
端的に言えば薬品の混和状態を有向グラフで整理し、薬品が混和されていない状態からすべての薬品が混和された状態へ遷移する道があるか探せばよい。
問題文における状態\(i\)の定義をそのまま使えば、こういうことだ。
・\(2^N-1\)頂点のグラフを用意し、状態\(i\)と頂点\(i\)が対応していると考える。
・状態\(i\)に対して、「まだ未混和の薬品を混和して状態\(j\)になる」かつ「状態\(j\)が安全である」ときに限って、頂点\(i\)から頂点\(j\)への有向辺が存在する。
この2条件を満たすグラフを考えると、頂点\(0\)から頂点\(2^N-1\)へ有限の辺をたどって遷移できるなら、対応する状態をたどって状態\(0\)から状態\(2^N-1\)に移動できる！
つまり、「薬品混和の問題」だと思っていたこの問題は、実は「グラフの遷移問題」と等価であり、単純なBFSやDFSで解くことができてしまうのだ！

各頂点から各頂点へ遷移可能かどうかを計算するにはビット演算をすればよい（当時の僕はこれすら覚束なかったが）だけなので、あとはやるだけ。
ざっくり頂点の個数だけ遷移先の可能性を考えないといけないので、時間計算量は\(O(2^NN)\)である。
これは今回の制約下\((N \leqq 16)\)では充分高速だと考えらえるので、この方針で実装しよう。

僕が書いたコードがこちら。

T = int(input())

for t in range(T):
    N = int(input())
    S = input()
    S = "0" + S

    Check = [ False for _ in range(2 ** N)]
    Check[0] = True
    for i in range(2 ** N):
        if Check[i]:
            for j in range(N):
                nex = i | (1 << j)
                # 既に状態iに混和済みの薬品ではなく(nex != i)、かつ遷移先が安全か?
                if nex != i and S[nex] == "0":
                    Check[nex] = True
    
    if Check[-1]:
        print('Yes')
    else:
        print('No')
最初にACしたときのコードを貼ろうと思ったが、あまりにも良くないコードだったのでリライトした。
NとSをすべて最初に受け取って保管したり、ビットシフトせずにforを1~N+1まで回して2 ** (j - 1)をandするという謎に迂遠なことをしたり……。
まあ当時の自分にはそっちの方が分かりやすかったんだと思うが、多分それは大抵の場合いい判断ではない。

以下余談。
これは「やり方を知っていればなんてことはない」という類の問題だろうと思う。
同値な言いかえをすると、「苦戦するんだったらやり方を知らない」ということでもある。
僕は当時苦戦した。オンタイム参戦だったが、この問題の解き方が全く思いつかなくて諦めた記憶がある。
何をしたらいいのか分からない。発想があるけど実装が分からないのではなく、発想がそもそもない。
ゆえに、解説を見たときに衝撃を受けた。簡単なグラフアルゴリズムを勉強したてだったのもあったと思う。
なにせ、「自分が知ったばかりの簡単な手法」が「考えても全く糸口すら見えなかった問題」を打ち倒してしまったのだ！ 驚きと言わずしてなんと言おうか。
何に打ちひしがれたのかは、今となっては判然としない。アルゴリズムの偉大さか、自らの無知の果てなさか、ともあれ、競技プログラミングって面白いと思った瞬間の1つがこれだった。

この問題のお陰でグラフアルゴリズムへの関心が高まったし、問題の見方を変えることの面白さを実感できたように思う。
個人的にはとても思い入れの深い問題である。
