ABC391E Hierarchical Majority Vote

問題文はこちらから。
数列を3つずつに区切って多数決を取り続けた最終結果を変えるのに必要な変更数を求める問題。

セグ木みたいな感じで各区間ごとの最多得票ビットを記録しておくことを考える。
0-indexedで、要素数が\(\frac{1}{2}(3^{N+1} - 1)\)の配列を用意する。
配列の\(\frac{1}{2}(3^N - 1)\)番目から\(\frac{1}{2}(3^{N+1} - 1) -1\)番目の要素には、それぞれ元のビット列の要素と同じ要素を格納しておく。
配列の\(p (< \frac{1}{2}(3^N - 1))\)番目の要素は、配列の\(3p+1,3p+2,3p+3\)番目（つまり自分の直下部）の要素の中で最多票のものと同じビットになる（pの値が大きい順に更新すれば、未定義の部分を参照することはない）。
こうしてみると、セグ木と同じように、自分の下の構造を参照して自分自身の値を決定する構造になっていることが分かるだろうか。この構造のことをセグメント構造と呼ぶことにする。

あとは、各要素を変更するときに掛かる最小コスト（以下「変更コスト」とする）を求める関数\(f\)を書けば、\(f(0)\)が求める答えである。
これは再帰的に書くことができ、ベースケース（つまり数列の最下部を変更する場合）については、明らかに自分自身を変更するのにかかるコストは1であるから、1を返せばよい。
そうでない場所については、自分自身をセグメント構造の\(p\)番目としたとき、自身の下部3つの要素(\(3p+1,3p+2,3p+3\)番目)を参照し、\(q=3p+1,3p+2,3p+3\)について、以下のようにする。
・セグメント構造の\(p\)番目の要素と\(q\)番目の要素が等しいとき、\(q\)の変更コストを\(f(q)\)とする。
・そうでない時、\(q\)の変更コストを0とする。
こうすることによって、\(f(p)\)は各\(q\)の変更コストであって最小のものから2つの和と一致する。
簡単な説明を行う。
自分自身の下部には、自分自身と等しい要素が2つもしくは3つある（過半数が反映されるため）。
・自身の下部に、自身と等しい要素がちょうど2つあった場合、変更すべき要素はそのうちのどちらかか片方でよく、このとき自身の変更コストは、2つのうち変更コストの小さい方となる。
・ちょうど3つあった場合、変更すべき要素はそのうち2つで、自身の変更コストについては変更コストが小さいものを順に2つ選べばよい。
よって、どちらの場合においても変更コストが小さい方から2つを取れば、自身の変更に掛かる最小コストが出せる。

以上を愚直に実装すると、セグメント構造の各セルが参照される回数は高々1回であるので、時間計算量は\(O(3^N)\)程度と見積もれる。
この制約下であれば充分に高速な実行が可能だろう。
実装例は以下の通り。

# セグメント構造のイニシャライズ
def segment_initialize(n, a):
    res = [ 0 for _ in range((3 ** (n + 1) - 1) // 2)]
    for i in range(3 ** n):
        res[-1-i] = a[3 ** n - 1 - i]
    p = (3 ** n - 1) // 2 - 1
    while p >= 0:
        vote_0 = 0
        vote_1 = 0
        for i in range(1, 3 + 1):
            if res[3 * p + i] == 0:
                vote_0 += 1
            else:
                vote_1 += 1
        if vote_0 > vote_1:
            res[p] = 0
        else:
            res[p] = 1
        p -= 1
    return res

# 要素pを変更するのにかかるコスト
def element_change(p, seg):
    if p >= (3 ** N - 1) // 2:
        return 1
    res = [0, 0, 0]
    v = seg[p]
    for i in range(1, 3 + 1):
        if seg[3 * p + i] == v:
            res[i - 1] = element_change(3 * p + i, seg)
        else:
            res[i - 1] = 0
    res.sort()
    return res[0] + res[1]

N = int(input())
A = list(map(int,list(input())))

Seg = segment_initialize(N, A)
print(element_change(0, Seg))
セグメントごとに区切る、各区間に対して再帰を行う、という発想がなかなか面白い。
この世界には色々似通っている構造があるなあと思うのでした。
