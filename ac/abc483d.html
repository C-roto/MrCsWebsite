ABC483D Glitchy Robot

問題文はこちらから。
ロボットアームをいっぱいいろんな場所に移動させる問題。

変更箇所は(変更しないというのも含めて)N+1通りの可能性があるが、これらをすべて愚直に検証している余裕はない。
ある箇所を変更した時、変わらないのはどういう場所かというのに着目する。
すると、例えば\(A_i\)の符号を反転させたとすると……
・\(A_{i-1}\)までは変更していない時と同じ処理をする
・\(-A_i\)だけ進む
・\(A_{i+1}\)以降の処理を行う（この結果は、「座標0を起点として\(A_{i+1}\)から\(A_{N}\)までの移動処理を行った結果」を\(-A_i\)だけズラした値になる）。
という感じになる。ただし、\(A_0,A_{N+1}\)はともに0であるとする。
つまり、\(-A_i\)に関する部分さえどうにかしてしまえば、その前後の部分の処理はほとんど使いまわせるのである。
よって、各\(A_i\)に対して、「座標0を起点として\(A_i\)から\(A_{N}\)までの移動処理を行った結果」を求めていけばよく、これは後ろから順に処理していけば比較的簡単に、かつ無駄なく計算できる（直前の処理結果を\(A_i\)だけずらしてみればよい）。
後ろから順にみた後、前から順に上記処理を順に行っていけば、各回について定数時間で計算できると見なせる。全体の時間計算量は\(O(N)\)程度で押さえられるだろう。
実装例は以下の通り。

N = int(input())
A = list(map(int,input().split()))

# 各Aの要素について、「その要素から移動を行った場合の、最終的な最大値と最小値」を求める
# (最小値、最大値、最終位置)
back = [(0, 0, 0)]
for i in range(N - 1, -1, -1):
    low, high, fin = back[-1]
    back.append((min(0, low + A[i]), max(high + A[i], 0), fin + A[i]))

# どれも符号を変更しなかった場合の最小値、最大値を引っ張ってきて、通った座標の数を算出。
back.reverse()
low, high, fin = back[0]
answer = high - low + 1

# 各要素について、A[i]の符号を反転させるとする
# その結果はA[i-1]までを順序通りにやった結果と、A[i+1]から移動を始めた場合の結果を-A[i]+(現在の座標)だけずらしたものを合わせたものになる
# 最小値も、その2つの結果のうち小さい方を取ればよい。最大値は大きい方を取ればよい。
now = 0
low = 0
high = 0
for i in range(1, N):
    L = min(low, back[i][0] - A[i - 1] + now)
    H = max(high, back[i][1] - A[i - 1] + now)
    answer = max(H - L + 1, answer)
    now += A[i - 1]
    low = min(low, now)
    high = max(high, now)
# 最後の要素を変更した時だけループ外で処理
L = min(low, -A[-1] + now)
H = max(high, -A[-1] + now)
answer = max(H - L + 1, answer)

print(answer)
