ABC217D Cutting Woods

問題文はこちらから。
木を切って、木材の長さを出力するぜって問題。

二分探索がすぐに頭をよぎった。
つまり、c=2のクエリが与えられたとき、「この地点より左にある切れ目の中で座標最大のものは？」という問いの答えを切れ目aとすると、aの次の切れ目の座標からaの座標を引いた値がちょうど求める木材の長さになる。
右端や左端の木材の場合バグるので、座標0と座標Lにも仮想的に切れ目がある状態としてよい。
あとはc=1のクエリを突っ込む時点でソートされている状態が保てればよいから、sortedcontainersでも使ってソートと要素追加を両立すれば問題ない。

sortedcontainersは現在持っている要素数を\(K\)としたとき、追加も要素の探索も\(O(\log_{}{K})\)で処理できるはずである。
よって、全体の時間計算量自体は\(O(Q\log_{}{Q})\)で抑えられるし、この制約下なら充分に高速である。実装例は以下の通り。

import sortedcontainers

cutted = sortedcontainers.SortedList([])

L, Q = list(map(int,input().split()))
cutted.add(0)
cutted.add(L)
for _ in range(Q):
    c, x = list(map(int,input().split()))
    if c == 1:
        cutted.add(x)
    else:
        a = cutted.bisect_left(x)
        print(cutted[a] - cutted[a - 1])
とりあえず今のAtcoder環境ならこれで通るが、問題出題の当時はSortedcontainersが使えなかったはず。
ユーザー解説にそのあたりを補足してくれている記事があったので読んでおきたい。
