Yukicoder No.4 おもりと天秤

問題文はこちらから。

おもりと天秤に関する問題。
単純な全探索を検討しようとすると、\(N\)個のおもりについて右と左のどちらに乗せるかを考えなければいけないため、\(2^N\)通りの可能性を考える必要がある。
しかし\(N \leqq 100\)ということは、単純計算でも最悪\(2^{100}\)回計算する必要があるから、おそらく無理だろう。

発想を変えてみよう。
すべてのおもりの重さの合計を\(W_{sum}\)としよう。
左右の皿に乗っているおもりの重さの合計が等しくなる時、両方の皿にはそれぞれ合計\(\frac{W_{sum}}{2}\)の重さのおもりが乗っているはずだ。
要するに、この問題は「このおもりの中から幾つかを選んで、おもりの重さの合計を\(\frac{W_{sum}}{2}\)ぴったりにできるか？」ということを聞かれているのである。
こう見ると、全探索の「効率的でなかった部分」が捨てられる。例えば、「どのおもりを選んだか」は重要ではない。
重要なのは「幾つかのおもりを選んで実現できる合計の重さ」をピックアップすることだ。
(例えば、重さがそれぞれ\(2,3,4,5\)であるようなおもりが1つずつあったとして、\(2,5\)を選んでも、\(3,4\)を選んでも、重さの合計はともに\(7\)になる。)

こう考えると、「ある重さが実現できるか？」にフォーカスすることで計算量を減らすことが期待できる。
この問題において、与えられる重さの最大値は\(100\)、与えられるおもりの数の最大値は\(100\)だ。
すると、重さの合計の最大値はたったの\(10000\)だ（後述の通り、実際はもう少し大きい）。\(2^{100}\)から見るとずいぶん減った！

以上のような前提があったうえで、実際どのように考えるかを簡潔に書いてみる。ズバリ、
・「\(i\)番目までのおもりを使って実現できる重さの一覧は？」を解きまくる
というものだ。
さっきの\(2,3,4,5\)の例で考えてみよう。便宜上、左から順に1番目のおもり、2番目のおもり……ということにする。
まず、おもりの重さの合計は\(14\)なので、\(15\)以上の重さが作れるかを考える必要はない。
この上でさっきの質問の答えを考えてみる。
・1番目のおもり(つまり重さ2のおもり)で作れる重さは、もちろん2のみだ。
つまり、この質問への答えは[2]だ。 ・2番目までのおもり(つまり重さ2,3のおもり)で作れる重さは、3と、1番目のおもりで作れた2と、その2に3を加えた5だ。
つまり、この質問への答えは[2,3,5]になる。
・3番目までのおもりで作れる重さは、4と、2番目までのおもりで作れた重さたちと、それらの要素たちにそれぞれ4を加えた値たちだ。
つまり、この質問への答えは[2,3,5,4,6,7,9]になる。
・4番目までのおもりで作れる重さは……全部列挙しないが、先ほどまでと同様だ。
すでに3番目までの質問の答えに含まれている値は重複しないように除くと、[2,3,5,4,6,7,9,8,10,11,12,14]が答えになる。
これを以て、もともと聞かれていた内容……つまり「天秤が釣り合うことはあるか？」を考えると、「4つのおもりを選んで重さ7は作れるので、釣り合うことはある」と答えることができる。

こう見ると、重さが同じになる選び方同士が同一視されていることがわかるだろうか？
\(2,3\)を選んでも、\(5\)単体を選んでも、結局「合計の重さが\(5\)である」ということは変わらず、そしてこの問題ではそれだけが重要なのである。

この問題の解答は以下の通り。時間計算量は\(O(W_{sum} \times N)\)で、今回の制約下においては普通に通るだろう。

import sys

N = int(input())
W = list(map(int,input().split()))

sW = sum(W)

if sW % 2 == 1:
    print('impossible')
    sys.exit()

pibot = sW // 2

DP = [ [False for _ in range(sW + 1)] for __ in range(N)]

for i in range(N):
    for j in range(i, N):
        DP[j][W[i]] = True

for i in range(N - 1):
    for j in range(sW + 1):
        if DP[i][j] == True:
            DP[i + 1][j] = True
            DP[i + 1][j + W[i + 1]] = True

ok_flag = False

for i in range(N):
    if DP[i][pibot] == True:
        ok_flag = True
        break

if ok_flag:
    print('possible')
else:
    print('impossible')
説明した方針とは少し違う（「\(i\)番目までのおもりで重さ\(w\)が実現できるか？」の答えをすべて保持している）が、本質的な考え方は一緒だ。

こうした問題群は競技プログラミングで「動的計画法」というくくりで説明される。
特定の問題を解決するための手段、というより、考え方の種類の1つだ。
「小さな部分問題を解き、結果をメモして使うことで、元の大きな問題を解く」というような話……だと自分は理解している。
ざっくり、
・全探索するにはとても時間が足りないような問題に対して、同じ結果になるものを「握りつぶして」1つにする
・直前の結果だけが次に影響する場合、その関係性を取り出して簡単な計算を行って結果を出せるようにする
のが主な目的だと捉えている。
高校数学で習う「漸化式」の考え方と近しいところがあると思うので、高校数学が得意だった人には飲み込みやすい概念だと思う。
まあ僕も使いこなせてなど到底いないのだが……。
